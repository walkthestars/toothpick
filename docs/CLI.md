# Toothpick CLI Reference

Toothpick is invoked via `toothpick <command>` (or `uv run toothpick <command>` inside a `uv` project environment). Every command emits deterministic JSON unless a text summary flag is selected.

---

## Global Conventions

- **Addresses**: All `<func_addr>`, `<base>`, and `<oep>` arguments accept hexadecimal (`0x140001000`) or decimal integers.
- **Database path**: Commands that read or write the analysis graph default to `--db toothpick.db`.
- **Binary selection (`--sha`)**: When `toothpick.db` holds a single ingested binary, `--sha` is inferred automatically. When multiple binaries exist in the same database, pass `--sha <binary_sha256>` (or a unique prefix where supported).
- **Exit codes**:
  - `0` — Success
  - `1` — General validation, storage, solver, or grounding error ( includes Epistemic Grounding Gate refusal)
  - `2` — `PACKED_ABORT(VM_PROTECTED)` (hypervisor/virtualized protector detected) or CLI usage error
  - `3` — Unknown or corrupt container format
  - `4` — Unsupported CPU architecture

## 1. Binary Triage & Unpacking

### `toothpick triage <target>`

Inspects file magic, headers, sections, imports, strings, and entropy to classify container format, CPU architecture, game engine, and packer signatures.

| Option | Default | Description |
|--------|---------|-------------|
| `--raw` | `false` | Treat `<target>` as a headerless raw firmware/memory blob |
| `--arch <arch>` | — | Architecture hint for `--raw` (`x86`, `x86_64`, `arm64`, `ppc`, `mips`) |
| `--base <hex>` | — | Base load address in hex for `--raw` (e.g. `0x80000000`) |
| `--static-only` | `false` | Mark report as offline static-only without live instrumentation |

```bash
toothpick triage GameAssembly.dll
toothpick triage firmware.bin --raw --arch arm64 --base 0x80000000
```

### `toothpick unpack <target>`

Decompresses UPX (`NRV2B`, `NRV2D`, `NRV2E`) and single-layer XOR loaders, or traces packer stubs in a Unicorn CPU micro-emulator (with simulated Windows TEB/PEB pages) until execution transfers to the Original Entry Point (OEP).

| Option | Default | Description |
|--------|---------|-------------|
| `--out <path>` | — | Output file path for the unpacked or reconstructed executable |
| `--detect-vm` | `false` | Run non-aborting forensic VM-protector detection (entropy + section heuristics) |
| `--hunt-oep` | `false` | Scan executable sections for compiler function-prologue signatures to candidate OEPs |
| `--reconstruct-pe` | `false` | Rebuild PE optional headers and section tables from a raw memory dump |
| `--oep <hex>` | — | Explicit OEP address when running `--reconstruct-pe` |

```bash
toothpick unpack packed.exe --out unpacked.exe
toothpick unpack suspect.exe --detect-vm --hunt-oep
toothpick unpack dump.bin --reconstruct-pe --oep 0x140001000 --out rebuilt.exe
```

## 2. Static Ingestion & IDA Import

### `toothpick static <target>`

Disassembles code sections with Capstone, splits basic blocks on branch targets, builds control-flow edges, computes reaching-definitions SSA facts, and writes everything to `toothpick.db` in SQLite WAL mode.

| Option | Default | Description |
|--------|---------|-------------|
| `--db <path>` | `toothpick.db` | SQLite database path |
| `--raw` | `false` | Treat `<target>` as a raw binary blob (requires `--arch`) |
| `--arch <arch>` | — | Architecture for `--raw`: `x86`, `x86_64`, `arm64`, `ppc`, `mips` |
| `--base <hex>` | — | Base address for `--raw` (e.g. `0x10000`) |
| `--static-only` | `false` | Force static-only mode |
| `--prefer-ghidra` | `false` | Populate C decompilation via PyGhidra when Ghidra is installed |
| `--json / --no-json` | `--json` | Format summary output as indented JSON |

```bash
toothpick static target.exe --db toothpick.db
```

### `toothpick ingest-metadata <metadata_file>`

Parses a Unity IL2CPP `global-metadata.dat` file and populates type definitions, fields, and method descriptors in `toothpick.db`.

| Option | Default | Description |
|--------|---------|-------------|
| `--db <path>` | `toothpick.db` | Target SQLite database |
| `--sha <sha256>` | `il2cpp_metadata` | Binary SHA-256 scope key for imported types |

### `toothpick ingest-ida <extract_json>`

Ingests an `ida_extract.v1.json` document generated by `icepick extract` into `toothpick.db`. Validates schema version `v1`, checks coverage/entropy gates, inserts functions and call edges, records an `UNGROUNDED` `ida_extract` provenance receipt, and routes symbol collisions against existing grounded names into the name-conflict queue.

| Option | Default | Description |
|--------|---------|-------------|
| `--db <path>` | `toothpick.db` | Target SQLite database |

```bash
toothpick ingest-ida extract.json --db toothpick.db
```

## 3. Bounded Graph & Program-Slice Queries (`toothpick query`)

All subcommands under `toothpick query` accept `--db <path>` and `--sha <binary_sha256>` either before or after the subcommand name.

### `toothpick query callers <func_addr>`
Lists functions that call `<func_addr>`.
- `--limit <int>` (default `50`, ceiling `1000`)

### `toothpick query callees <func_addr>`
Lists functions called by `<func_addr>`.
- `--limit <int>` (default `50`, ceiling `1000`)

### `toothpick query def_use <func_addr>`
Returns SSA reaching-definition chains inside `<func_addr>`.
- `--var <name>` — Optional register or SSA variable filter (e.g. `rax`, `rcx`)
- `--limit <int>` (default `50`, ceiling `1000`)

### `toothpick query slice <func_addr>`
Computes an intra-function backward or forward dataflow slice over SSA facts.
- `--target <reg>` (**required**) — Register or SSA variable to slice from
- `--direction backward|forward` (default `backward`)
- `--max-depth <int>` (default `10`, ceiling `64`)
- `--limit <int>` (default `50`, ceiling `1000`)

### `toothpick query func <func_addr>`
Retrieves the stored function record (name, prototype, block count, IR p-code, and decompiled C).
- `--max-lines <int>` (default `200`) — Truncates long IR/decompiler bodies with an explicit `[TRUNCATED]` notice.

## 4. Constraint Solving, Dynamic Grounding & Memory Scanning

### `toothpick solve <func_addr>`

Lifts basic-block instructions into Z3 `BitVec` formulas and solves for concrete input register assignments that reach a target block.

| Option | Default | Description |
|--------|---------|-------------|
| `--target-block <addr>` | — | Target basic-block address (hex or int) to solve reachability for |
| `--db <path>` | `toothpick.db` | SQLite database path |
| `--sha <sha256>` | inferred | Binary SHA-256 |
| `--timeout <float>` | `5.0` | Solver timeout in seconds |

### `toothpick ground <func_addr>`

Captures runtime execution state (registers, stack arguments, return values) and writes a `GROUNDED` verification receipt to `toothpick.db`.

| Option | Default | Description |
|--------|---------|-------------|
| `--db <path>` | `toothpick.db` | SQLite database path |
| `--sha <sha256>` | inferred | Binary SHA-256 |
| `--pid <int>` | — | Attach Frida to a running process ID |
| `--spawn <path>` | — | Spawn executable under Frida instrumentation |
| `--backend frida\|ceserver` | `frida` | Dynamic grounding backend (`frida` or `ceserver`) |
| `--host <str>` | `127.0.0.1` | Remote host for `ceserver` backend |
| `--port <int>` | `52736` | Remote TCP port for `ceserver` backend |
| `--static-only` | `false` | Record a static structural grounding receipt without attaching to a process |
| `--timeout <float>` | `5.0` | Capture timeout in seconds |

### `toothpick scan <pattern>`

Scans process memory, raw dump files, or a `ceserver` daemon with hard result caps.

| Option | Default | Description |
|--------|---------|-------------|
| `--type <kind>` | `i32` | `i8`, `u8`, `i16`, `u16`, `i32`, `u32`, `i64`, `u64`, `f32`, `f64`, `string`, `hex`, `pointer` |
| `--file <path>` | — | Scan an offline memory dump or raw binary file |
| `--base <hex>` | `0x0` | Base address of `--file` |
| `--pid <int>` | — | Scan a live process via Frida |
| `--backend buffer\|frida\|ceserver` | `buffer` | Memory backend (`buffer`, `frida`, or `ceserver`) |
| `--host <str>` / `--port <int>` | `127.0.0.1:52736` | Endpoint for `--backend ceserver` |
| `--session <id>` | — | Existing scan session ID to refine/filter |
| `--comparison <op>` | `exact` | Refinement operator (`exact`, `increased`, `decreased`, `changed`, `unchanged`) |
| `--export-reclass <path>` | — | Export matched addresses as a ReClass.NET `.rcnet` XML project |
| `--limit <int>` | `50` | Maximum matches returned (ceiling `1000`) |

## 5. Mod Scaffolding & Code Generation

### `toothpick build <target>`

Generates engine-specific mod projects. Requires a `GROUNDED` receipt in `toothpick.db` unless `--allow-unverified` is set.

| Option | Default | Description |
|--------|---------|-------------|
| `--engine unity\|unreal\|godot` | `unity` | Target engine (`unity`, `unreal`, or `godot`) |
| `--mod-type <kind>` | engine default | `bepinex_csharp`, `ue4ss_lua`, `native_cpp`, `gdextension`, or `gdscript` |
| `--hook-type prefix\|postfix\|replace` | `postfix` | Harmony hook type (`prefix`, `postfix`, or `replace`) |
| `--db <path>` | `toothpick.db` | SQLite database path |
| `--sha <sha256>` | inferred | Binary SHA-256 |
| `--out <dir>` | `./build/<name>` | Output directory for generated project |
| `--name <str>` | `ToothpickMod` | Plugin/mod name |
| `--logic <code_str>` | — | Optional custom code snippet to insert into the hook body |
| `--godot-version 3\|4` | `4` | Target Godot major version |
| `--compile` | `false` | Run `dotnet build` to compile the generated C# project into a `.dll` |
| `--allow-unverified` | `false` | Bypass the Epistemic Grounding Gate (marks output `UNVERIFIED`) |

### `toothpick hook build`

Generates a standalone CMake C++ MinHook injected-DLL project gated by grounding receipts.

| Option | Default | Description |
|--------|---------|-------------|
| `--target <addr>` | **required** | Target function address to hook (hex or decimal) |
| `--out <dir>` | **required** | Output directory for the generated hook project |
| `--db <path>` | `toothpick.db` | SQLite database path |
| `--sha <sha256>` | inferred | Binary SHA-256 |
| `--name <str>` | `hook` | Project/DLL target name |
| `--arch x86\|x64` | `x64` | Target architecture of the injected DLL |
| `--prologue-hex <hex>` | — | Optional prologue bytes (hex) to validate |
| `--allow-unverified` | `false` | Bypass the Epistemic Grounding Gate |

### `toothpick lua <subcommand>`

Scaffolds and packages Lua/Steam Workshop mods:
- `toothpick lua build --class com.foo.Bar --method tick --desc "()V" --out ./lua_mod --name "My Mod" --mod-id MyMod --db toothpick.db` (`--allow-unverified` optional)
- `toothpick lua pack <mod_dir> --out mod_bundle.zip`
- `toothpick lua patch-emit <orig_file> <patched_file> --out patch.json`

### `toothpick pck <subcommand>`

Inspects and extracts Godot `.pck` resource archives with path-traversal protection:
- `toothpick pck list <archive.pck>`
- `toothpick pck extract <archive.pck> --out ./extracted`

## 6. Version Rebase, RTTI, JVM, Profiling & Advanced Analysis

### `toothpick rebase <new_target>`

Computes function-to-function port mappings from a baseline binary in `toothpick.db` (`--old-sha`) to `<new_target>` using exact instruction-digest matching, structural CFG/call-graph similarity, optional 64-D semantic embeddings (`--semantic`), and optional external diff candidates (`--priors candidates.json` from `icepick diff-import`).

```bash
toothpick rebase game_v2.exe --old-sha <old_sha> --db toothpick.db --semantic --out offset_map.json
```

### `toothpick rtti scan <file>`

Scans candidate vtable addresses in `<file>` (loaded at `--base`) for MSVC RTTI `CompleteObjectLocator` structures (`--arch x86|x64`, bounded by `--max-vtables`, default `50`) and stores recovered classes and demangled names in `toothpick.db`.

```bash
toothpick rtti scan game.exe --base 0x140000000 --vtables 0x14001000,0x14002000 --db toothpick.db
```

### `toothpick struct`

Synthesizes structure field layouts from a memory dump (`--file`) or live process (`--pid`) and exports ReClass.NET XML (`rcnet`), C++, C#, or JSON (`--format rcnet|cpp|csharp|json`).

```bash
toothpick struct --file dump.bin --address 0x140001000 --size 0x100 --name PlayerState --format rcnet --out player.rcnet --db toothpick.db
```

### `toothpick jvm ingest <path>`

Parses a `.class` file or `.jar` archive into `toothpick.db` (methods, constant-pool call edges, and classes/fields) with zip-boundary safety checks.

```bash
toothpick jvm ingest game.jar --db toothpick.db
```

### `toothpick profile <subcommand>`

Imports sampling profiler captures (`auto`, `vtune`, `etw`, `perf`, `async`, `jfr`) and correlates samples against `toothpick.db` functions:
- `toothpick profile import <csv_or_json> --db toothpick.db --format auto|vtune|etw|perf|async|jfr`
- `toothpick profile hottest --db toothpick.db --top 50`

### `toothpick cdb`, `toothpick dbi`, `toothpick taint`, `toothpick bench`

- `toothpick cdb --dump crash.dmp` or `toothpick cdb --pid 1234 --cmd "kb" --cmd "r"` — Headless WinDbg/`cdb.exe` triage.
- `toothpick dbi --target <file> --engine unicorn --trace-bbs --db toothpick.db` — Dynamic binary instrumentation trace, Pin/DynamoRIO tool generator (`--generate pin|dynamorio`), or trace log parser (`--parse`).
- `toothpick taint --binary <file> --func 0x140001000 --source rcx --db toothpick.db` — Intra-procedural taint propagation or Triton/Manticore script exporter (`--export triton|manticore`).
- `toothpick bench run ...` / `toothpick bench compare ...` — Timing benchmark runner and regression comparator.

### `toothpick show <func_addr>` & `toothpick ledger`

- `toothpick show <func_addr> --db toothpick.db` — Unified JSON inspection overlay (function metadata, callers, callees, SSA facts, grounding receipts, trace events).
- `toothpick ledger --db toothpick.db [--events-log events.log]` — Token and cost accounting summary.
